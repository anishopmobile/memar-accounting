# نقشه معماری و مهاجرت امن پنل Tabler (۱۴۰۵/۰۷/۲۹)

## ۱. ساختار اجرا و ارتباط صفحات با دیتابیس
- ورودی مدیریت: `index.php`، مسیردهی با allowlist پارامتر `page` به ۲۲ صفحه در `pages/`؛ زبان `fa` و جهت `rtl`.
- `assets/php/boot.php` ورود را کنترل می‌کند؛ `assets/php/auth.php` نشست و توکن CSRF را مدیریت می‌کند.
- `assets/php/db.php` اتصال MySQL و ساخت/ترمیم تدریجی جدول‌های اصلی را انجام می‌دهد. **رندر پنل نباید با مهاجرت یا تغییر داده همراه شود.**
- `index.php` اسکریپت‌های سراسری jQuery و `main.js`، ماژول فاکتور، بسته، امور جاری و بخش پرداخت را در ترتیب قبلی بارگذاری می‌کند.
- فاکتور فروش/خرید/پیش‌فاکتور: `invoice.js` → `invoice_save.php`/`invoice_products.php` → `invoice_common.php` → `invoices`، `invoice_items`، `products`، `stock_movements`. واحدهای اندازه‌گیری از `product_units` و اجزای بسته از `bundle_components` و snapshot تاریخی خوانده می‌شوند.
- برگشت فروش: `sales-return.js` و `sales_return_common.php`؛ وابسته به فاکتور اصلی و جدول‌های `sales_returns` و `sales_return_items`.
- کالاها/خدمات و دسته‌بندی‌ها: `product_action.php`، `product_list.php`، `category_action.php`، `bundle_action.php` و جدول‌های محصول/واحد/بسته. ثبت معیوبی/مرجوعی از endpointهای مستقل استفاده می‌کند.
- داشبورد: کوئری‌های `dashboard.php` و جدول فروش/کالا/مشتری، نمودار `chart.umd.min.js` **محلی** و داده‌های کم‌موجودی.
- مشتری/تأمین‌کننده: `save_customer.php`/`save_supplier.php`، گزارش بدهی به فاکتورها و جدول اشخاص متکی است.
- امور جاری: `current-affairs.js` و زیرماژول `current_affairs/ca_loader.php` / `ca_repository.php`؛ جداول دسته‌بندی/فیلدهای پویا و رکوردهای مربوط به آن‌ها.
- یادداشت‌ها: `pages/notes.php`، `main.js` و `note_action.php` → جدول `notes` با فیلدهای متن/رنگ/موقعیت.
- حساب و تنظیمات: توابع Auth، `store_settings.php`، `invoice_settings.php`، `currency_settings.php` و جداول تنظیمات؛ واحد ذخیره مبالغ حسابداری تومان باقی می‌ماند.
- پرداخت: `payment-forms`، `payment-transactions`، تنظیمات پیامک/درگاه و `assets/php/payment/payment_loader.php`. **طرح دیتابیس Payment مهاجرت CLI مستقل دارد؛ هیچ کد پرداخت/مبلغ ریالی آن دستکاری نشده است.**

## ۲. محدوده پیاده‌سازی رابط
- کتابخانه `@tabler/core@1.6.1` در `assets/vendor/tabler/` ذخیره و با SHA256 ثبت شد؛ CSS RTL به‌صورت محلی پیش از CSS قدیمی بارگذاری می‌شود.
- CSS قدیمی پس از Tabler و فایل `assets/css/tabler-integration.css`، `navbar-toolbar.css` و `dashboard-about.css` پس از هر دو بارگذاری می‌شوند؛ لایه سازگاری با `body.tabler-admin` محدود است.
- به‌جای جایگزینی modalهای موجود با Bootstrap، modalها با کلاس قدیمی `.modal.open` مدیریت می‌شوند؛ `tabler.min.js` به‌عنوان سورس محلی نگه‌داری شده و **برای جلوگیری از تداخل Bootstrap Data API در پنل فعال نیست**.
- `assets/js/layout.js` صرفاً باز/بسته کردن drawer موبایل، فوکوس/کلید Escape و حالت ARIA را کنترل می‌کند.
- در دسکتاپ تمام ورودی‌های منوی بالا در **یک ردیف** قرار می‌گیرند و در موبایل/تبلت drawer راست‌چین حفظ می‌شود. کالاهای معیوب زیر فاکتورها، یادداشت‌ها و تمام بخش پرداخت زیر تنظیمات قرار دارند. جداول در `.table-wrapper` اسکرول مستقل افقی دارند؛ بخش آمار و عملیات سریع واکنش‌گرا شده است.
- یادداشت‌های موبایل به‌جای موقعیت‌یابی absolute به چیدمان grid می‌روند؛ drag در این حالت غیرفعال است و ویرایش متن موقعیت desktop را بازنویسی نمی‌کند.
- صفحات login/register و پرداخت عمومی (`pay.php`) خارج از shell مدیریت باقی مانده‌اند. **صفحه ورود به‌صورت ایمن و فقط در لایه نمایشی** از CSS RTL محلی Tabler و `login-tabler.css` استفاده می‌کند؛ PHP احراز هویت، CAPTCHA، CSRF و محدودکننده تلاش‌ها دست‌نخورده‌اند.

## ۳. دروازه‌های آزمایش
- تست‌های قبلی PHP/JS، فاکتور خرید و فروش، برگشت، بسته، اکسل، مالی و امنیت بدون تغییر اجرا می‌شوند.
- `tabler_ui_smoke.sh`: هر ۲۲ route را با نشست معتبر و MySQL جداگانه رندر می‌کند؛ منابع local، RTL، قرارداد shell و خطاهای سرور را بررسی می‌کند.
- `tabler_browser_smoke.sh` / `admin_ui.test.cjs`: Chromium در هشت عرض ۱۴۴۰، ۱۲۸۰، ۱۱۰۰، ۱۰۲۵، ۱۰۲۴، ۷۶۸، ۳۹۰ و ۳۶۰، منوی موبایل، جدول/صفحات، ناوبری و مودال قدیمی افزودن خدمت را بررسی می‌کند.
- راه‌اندازی دیتابیس تست، مهاجرت CLI پرداخت را **فقط داخل دیتابیس موقت CI** اجرا می‌کند، نه روی داده‌های واقعی.
- آزمایش‌های اتوماتیک جای آزمون دستی تصویر/PDF، touch در گوشی‌های واقعی، ابزار پرداخت بانک و تمامی فرم‌های تأییددار را نمی‌گیرند؛ قبل از انتشار سرور واقعی اسکرین‌شات/رفتار و داده‌های پشتیبان باید مجدداً بررسی شوند.

- `login_ui.test.cjs`: پوشش دسکتاپ و موبایل با CAPTCHA روشن/خاموش، توکن CSRF نامعتبر، مشاهده/مخفی‌کردن رمز و منابع کاملاً محلی؛ `auth_http_test.php` صحت کامل ثبت‌نام/ورود/خروج/کپچا/محدودیت تلاش را در MySQL موقت CI بررسی می‌کند.
- داشبورد: چهار عملیات سریع و چهار کارت مالی در یک ردیف دسکتاپ؛ نمودار فروش کنار آخرین فاکتورها، گزارش کم‌موجودی در یک ردیف کامل.
- برند رابط در صفحات اصلی از «کوشا حساب» به **«حسابداری معمار»** تغییر کرد؛ نام انگلیسی **Memar Accounting** است.

## مورد شناخته‌شده خارج از محدوده مهاجرت
در تست مرورگر، کد موجود `assets/js/payment-transactions.js` هنگام دریافت لیست تراکنش‌ها تابع تعریف‌نشده `renderPagination` را فراخوانی می‌کند. این اشکال پیش از تغییر Tabler در ماژول Payment وجود داشته و به درخواست مالک، هیچ کد Payment در این انتشار تغییر نکرده است. آزمون مرورگر فقط این خطای مشخصِ ازپیش‌موجود را به‌عنوان استثنای مستند لحاظ می‌کند، نه سایر خطاهای JavaScript.

## ۴. ضمانت وابستگی
هیچ درخواست مرورگر به CDN یا NPM برای اجرای پنل نیاز ندارد. فونت Estedad، FontAwesome، jQuery، Chart.js، datepicker و Tabler همگی از پوشه `assets` سرو می‌شوند. دانلود Playwright و Chromium فقط در محیط **آزمون CI** مجاز است و بخشی از وابستگی زمان اجرای سایت نیست.

## ۵. محدوده تغییر فایل‌ها
فقط پوسته مدیریتی مشترک، استایل و JavaScript رابط، عملیات سریع داشبورد، موقعیت‌گذاری یادداشت‌ها، دارایی‌های Tabler، اسکریپت‌های آزمون، مستند معماری و تنظیمات CI؛ هیچ endpoint مالی/پرداخت/جدول تولیدی تغییر نکرد.
